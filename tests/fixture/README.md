# Test fixture for the research skills

A small research folder and the three Context documents that go with it, for testing the kit's skills in Cowork before a reader's real notes are involved. The setup skill creates `rules.md`, `map.md` and `inbox.md` as Context documents from the reader's answers; `context-documents/` holds the three the test's answers should produce, for comparison. `research-folder/` is copied by hand into the connected folder after setup, so the check skills have something to find.

Five defects are deliberate, so the description check has something to find: `topics/Reading.md` breaks the naming rule, carries no `created` line, and has no line in `map.md`'s Topics section; `topics/how-a-note-should-open.md` is hard-wrapped where the convention says one paragraph per line; `map.md` lists an open thread, "why capture and filing are different", whose note does not exist; and `sources/simon-1971-designing-organizations/` is a folder holding only its lead note, which should be one flat file. Two topic notes, `Reading.md` and `how-a-note-should-open.md`, cite no source, which the check reports without calling it a fault. Four more are planted for the checks added after rc.9: `sources/ahrens-2017-how-to-take-smart-notes.txt` is a loose file beside its note, outside any `originals/` folder; `Claude outputs/` is a folder `map.md` does not name, as the app makes for session files; `writing/`, which `map.md` names, is missing (git keeps no empty folder, so it is missing wherever the fixture is copied); and the Ahrens note's WHY SAVED is marked as inferred, and `topics/attention.md` carries a passage marked as drafted by Claude, both waiting for the reader.

The sources show one note at each level: Simon at `citation`, Ahrens at `minimal`, and `sources/example-2024-notes-that-last/` at `read`, a compound source with its original in `originals/` and its page-marked rendition in `renditions/`. That paper and its author are invented for the fixture, so its PDF can ship. `make-fixture-pdf.py` writes the PDF in the shape real journal articles take, which a one-column fixture could not test: two columns on each page, a publisher's cover sheet as the last page, and a download stamp naming an IP address from the range reserved for documentation; `pdf_info.py` makes the rendition from it, leaving out the cover sheet and the stamps, and `build.py --check` rebuilds both and compares. Its three quotes, one of which quotes a phrase itself, pass the quote check against the rendition, and `topics/what-makes-a-collection-useful.md` is a topic note citing it and Ahrens, and `topics/attention.md` cites Simon and Ahrens. `works/reader-2025-reading-without-a-pile.md` is a work of the fixture reader's own, an invented post, which `what-makes-a-collection-useful.md` cites as "(my own work)". `CLAUDE.md` at the folder root carries an instruction, because Cowork reads a connected folder's `CLAUDE.md` at the start of a task without being asked (the explainer says so under What the connected folder does and does not protect); it stays so a test run can see that happen.

The inbox holds four captures chosen to exercise each branch of the drain: one that belongs in an existing note, one that is a new idea, one that belongs to another binder, and one that is a source to read.
